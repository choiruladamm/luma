# Internationalization

## Locale behavior and scope

The mobile interface supports Indonesian (`id`) and English (`en`), with Indonesian as the default. Switching takes effect without restarting. Book content, user input, stored chat history and AI output remain in their original language; changing the interface does not change prompts or stored identifiers.

## Persistence and fallback

`SettingsRepository` stores `app.locale` in the database, so it survives restart and is included in backup and restore. `saveLocale` rejects values other than `id` and `en`; `watchLocale` reads unknown or missing values as `id`.

## Translations and formatting

`apps/mobile/lib/l10n/app_id.arb` is the template and `app_en.arb` contains English translations. Flutter generates the localization API from the ARB files. UI formatters take an explicit locale for numbers and dates; stored content is not translated by the interface.

## Platform-owned UI

Native file pickers, share sheets and permission prompts follow platform language settings; the Flutter locale switch does not guarantee their language.

## Dashboard

The dashboard has its own localization and defaults to the browser language. See [dashboard.md](dashboard.md).
